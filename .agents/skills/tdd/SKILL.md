# tdd — diet-assistant のテスト駆動開発レシピ

実装をテストから始めるための、このプロジェクト固有の手順。
テストスイート全体・lint・型チェックのコマンドは `AGENTS.md` の「コマンド」節を参照する。

## テストの置き場所と実行

- テストファイルは `tests/test_<対象>.py` に置き、テスト関数は `test_<振る舞い>` と命名する
- サイクル中は `.venv/bin/pytest tests/test_<対象>.py -q` で対象ファイルだけを実行する
- さらに絞る場合は `.venv/bin/pytest tests/test_<対象>.py::test_<振る舞い> -q` を使う

## サイクル

1. **Red**: これから実装する振る舞いを 1 つ選び、期待を表すテストを書く。実行して意図した理由で失敗することを確認する。import error や typo による失敗は Red としない
2. **Green**: テストを通す最小の実装を書く。先回りして別の振る舞いまで一般化しない
3. **Refactor**: テストが通った状態を保ったまま重複・命名を整理し、対象テストを再実行する
4. 1 に戻る。区切りがついたら `AGENTS.md` の「作業の進め方」に従って全体を検証する

## このプロジェクトの流儀

- SQLiteを使うテストは `tmp_path` または `db_path` fixture を使い、本番の `data/diet.db` を触らない
- CLIの振る舞いは `diet_assistant.cli.main` を一時ルート付きで呼び出し、終了コード・出力・SQLiteの永続化結果を確認する
- 日付に依存するロジックでは日付を明示的に渡し、実行日によって結果が変わらないテストにする
- DB更新では成功経路だけでなく、制約違反時の失敗と既存データが保持されることも必要に応じてテストする
- 型ヒントを付け、pytestのfixtureや出力を扱う型もBasedpyright recommendedモードで通る形にする
