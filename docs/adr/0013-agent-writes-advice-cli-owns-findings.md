# フィードバックの文面はエージェントが書き、CLIは分析結果（findings）だけを正本として持つ

- ステータス: 承認済み
- 日付: 2026-07-25

`services/advice.py` の3関数は if/else で定型文を選ぶだけで、分岐は各3〜4通りしかなく、
返す文字列が実データを参照していなかった。**CLIからフィードバックの文面生成をやめ**、
数値と参照値を持つ分析結果（findings）の計算だけを担わせる。フィードバックの文面はエージェントが
findings から書き、`diet advice save` で `advice_history` へ保存し、レポートはそれを埋め込む。

## コンテキスト

週次フィードバック（旧 advice.py:150-166）は「記録不足／目標+150 kcal超／それ以外」の3択で、
超過時に返す「最も頻度の高い間食を1日200 kcal以内にする」は分岐に固定された文字列であり、
間食の実績を一度も見ていなかった。実データでは間食は10件・平均106 kcalで、
このフィードバックは根拠がないだけでなく誤りだった。同時に、集計している栄養素
（protein / fat / carbohydrates / fiber / sodium）はフィードバックの判定に一切使われず、
カロリー軸では出てこない実信号（夕食が1日の43%、繊維不足、高塩の日）が捨てられていた。

分岐を増やす方向では直らない。軸が5つになれば分岐は積算し、「根拠のない文字列を
書けてしまう」という構造は残る。文面の生成をやめれば、裏付けのない主張は書く場所がなくなる。

## 決定

- CLIは `services/analysis.py` の findings を計算する。各 finding は
  `group`（`goal` / `calorie` / `nutrition`）、実測値、参照値と参照根拠、
  期間と `sample_days`（根拠の量）を必ず持つ。
- `diet advice today|weekly` と `diet meal add` は findings を返す。文面は返さない。
- エージェントが書いたフィードバックは `diet advice save` で `advice_history` に保存する。
  会話履歴を正本にしないため、レポートへ載る文面はDBを経由する。
- ADR 0011 の結果のうち「`diet report` と `diet advice` がCLIで生成した文言は
  数値もフィードバック文も正本なのでこの方針で書き換えない」を置換する。**正本は findings の数値**で、
  フィードバック文はエージェントの著述物として `advice_preference` に沿わせる。

## 検討した代替案

- **定型文を残し、findings の数値で束縛する** — テンプレートに finding の数値を埋め、
  裏付けのない文は書けない形にする案。CLI単体でフィードバックが完結する利点があったが、
  「目標に対して順調か」を語り分けるには表現の幅が足りず、結局品質の下限を固定するだけだった。
  利用者は常にエージェント経由で使うため、下限を守る価値がコストに見合わない。
- **advice.py の分岐を増やす** — 上記のとおり、固定文字列という構造的問題が残る。

## 結果

- **CLI単体ではフィードバックの文面が出なくなる。** `diet report` は保存済みのフィードバックがあれば埋め込み、
  なければ findings の事実だけを載せる。
- レポート生成は2パスになる（`diet advice` → 執筆 → `diet advice save` → `diet report`）。
  write-report / record-meal スキルの手順をこの順に書き換える。
- `advice_history` の意味が変わる。`summary`・`details` はエージェントが書いた文面、
  `evidence` は執筆時点の findings のスナップショット。種別・期間ごとに最新1件だけを
  保持する規則（ADR 0010）はそのまま。
