# 目標の削除は論理削除にし、planは残す

- ステータス: 承認済み
- 日付: 2026-07-25

目標を物理削除すると`plans`が`ON DELETE CASCADE`で消え、過去のレポートが根拠にしていた
摂取目標を復元できなくなる。そのため`goal delete`は`goals.deleted_at`を立てる論理削除とし、
同時に`status`を`inactive`へ落として一覧・activate・評価から除外する。過去日のレポートが引く
plan参照（`reporting.py`）は削除済み目標のplanも対象のままにする。これが記録を残す目的そのもの。

## 検討した代替案

- **`plans`のFKを`ON DELETE RESTRICT`にする**: `goal add`が必ず`save_plan`を呼ぶため、
  全ての目標が作成時点でplanを1件持つ。RESTRICTでは誤登録の目標すら削除できなくなる。
- **削除前に目標とplanをファイルへ退避する**: 正式な記録はSQLiteを正本とする方針に反し、
  レポートの根拠を正本の外に置くことになる。
- **既存の`status='cancelled'`を流用する**: cancelledは「目標をやめた」というユーザーの
  意思決定の記録でレポートに出す価値があり、「一覧から隠す」削除操作とは意味が違う。

## 結果

物理削除の経路は当面提供しない。必要になったら`goal purge`として別途用意する。
